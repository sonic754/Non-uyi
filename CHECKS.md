## Проверки и воспроизведение

Из корня репозитория:

```sh
npm test
npm run check
npm run test:logic --prefix non-uyi-ai
npm test --prefix non-uyi-ai
npm run build --prefix non-uyi-ai
npm run evaluate:analysis
npm run evaluate:analysis -- --retry-failed
npm start
```

Оценщик полного анализа берёт именно 20 исходных сообщений из `claude.md`,
добавляет 10 новых случаев с опечатками, смешанным языком, несколькими товарами,
неизвестными данными, отрицанием заказа и попытками управлять моделью.
Паузы между запросами уменьшают вероятность превышения квоты. Технические
ошибки 502/504 повторяются один раз; 429 остаётся в отчёте для последующего
запуска `--retry-failed`. Отчёт `analysis-evaluation-results.json` не содержит
исходных сообщений, адресов и черновиков; файл исключён из Git.

Браузерные сценарии запускались в отдельном headless Chrome через Playwright.
Сценарии UI используют явно подставленные API-ответы и демопримеры, чтобы
воспроизводимо проверить ошибки, повторы, фильтры, CSV и вёрстку. Реальный
Gemini проверяется отдельным полным оценщиком. JavaScript-ошибок страницы
не обнаружено. Встроенный cua_repl не запустился из-за ошибки окружения.

## Как устроено приложение

React хранит сообщения, фильтры и статистику в состоянии. В пакетном режиме
каждая непустая строка становится отдельным сообщением. Запросы выполняются
последовательно; у каждого своё время ожидания и AbortController. Ошибка одного
сообщения сохраняет его в поле ввода, остальные результаты остаются в истории.
История очищается при обновлении страницы, как указано в интерфейсе.

API-адаптер отправляет сообщение на локальный `/api/analyze`. Node-сервер
проверяет тело запроса и вызывает Gemini с полным промптом и JSON-схемой.
Правила Фирдавса определяют категорию и язык; правила Бехруза извлекают данные
и создают черновик. Парсер проверяет шесть полей и принудительно убирает ответы
жалоб и спама. Адаптер преобразует `product` в `name` для таблицы React.
Ключ в браузер не передаётся. JSON-схема соответствует механизму
[структурированных ответов Gemini](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en).

Если модель написала «ваш заказ принят/подтверждён» или «buyurtmangiz
qabul qilindi/tasdiqlandi», сервер заменяет текст на черновик передачи запроса
владельцу на том же языке. Это правило отдельно проверено тестами.
React-тесты ограничены одним рабочим процессом: параллельный запуск на этом
компьютере однажды завершился ошибкой нехватки памяти.

CSV формируется из текущих отфильтрованных заказов. Поля заключаются в кавычки,
кавычки внутри удваиваются, потенциальные формулы нейтрализуются. UTF-8 BOM
помогает табличным редакторам распознать русский и узбекский текст.

## Границы проверки

Это тестовый набор проекта, а не неизвестные сообщения жюри. Присутствие
нужного языка в черновике и отсутствие числовых цен проверяется эвристически;
стиль, все бизнес-факты и все возможные обещания требуют просмотра оператором.
HTTP 429 и тайм-ауты остаются возможными внешними ошибками Gemini; они не
превращаются в фиктивный успешный ответ. Черновики клиентам автоматически не
отправляются. Устную защиту участников программные тесты подтвердить не могут.
